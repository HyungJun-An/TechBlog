## JPA 아키텍처 — 규격과 구현체

## MyBatis vs JPA

두 프레임워크는 목적이 다릅니다. MyBatis는 SQL을 직접 작성하는 방식, JPA는 객체 중심으로 SQL을 자동 생성하는 방식입니다.

| 구분 | MyBatis | JPA (Spring Data JPA) |
|---|---|---|
| **중심** | SQL | 객체(엔티티) |
| **장점** | 복잡 쿼리·다이나믹 SQL에 강함 | CRUD 빠름, SQL 작성 부담 없음 |
| **단점** | SQL·맵퍼 학습 부담, 객체 변환 직접 처리 | 추상화가 높아 내부 동작 이해 필요, 복잡 조인은 어려움 |
| **실무** | 금융·통신 등 복잡 도메인 | 게시판·쇼핑몰 등 단순 CRUD |

```java
// MyBatis: SQL을 직접 작성
// StudentMapper.xml
// <select id="findByName" resultType="StudentVO">
//   SELECT * FROM student WHERE name = #{name}
// </select>

// JPA: 메서드 이름으로 쿼리 자동 생성
interface StudentRepository extends JpaRepository<StudentEntity, Long> {
    List<StudentEntity> findByName(String name);
    // → Hibernate: SELECT * FROM student WHERE name = ?
}
```

> **실무 하이브리드**: 단순 CRUD는 JPA로 빠르게, 복잡한 통계/다중 조인 쿼리는 MyBatis나 QueryDSL로 처리하는 조합이 많습니다.

## Hibernate ORM — 더티체킹과 영속성 컨텍스트

ORM(Object-Relational Mapping)의 핵심은 **객체 상태 변화를 자동으로 감지해 DB에 반영**하는 것입니다.

```java
// 더티체킹(Dirty Checking) — save() 없이 자동 UPDATE
@Transactional
public void updateName(Long seq, String newName) {
    // findById → 엔티티를 영속성 컨텍스트(1차 캐시)에 등록
    StudentEntity student = repo.findById(seq).orElseThrow();

    student.setName(newName);
    // ← save() 호출 없음!
    // 트랜잭션 커밋 시점에 Hibernate가 상태 변화 감지
    // → UPDATE student SET name = ? WHERE seq = ? 자동 실행
}

// 영속성 컨텍스트 4가지 상태
// 비영속(new)    → new StudentEntity() — JPA 모름
// 영속(managed)  → em.persist() 또는 repo.findById() 이후
// 준영속(detached)→ 트랜잭션 종료 후 또는 em.detach() 이후
// 삭제(removed)  → em.remove() 또는 repo.delete() 이후
```

## JPA 엔티티 어노테이션

<JpaAnnotationsGuide />

### 완전한 엔티티 예제

```java
import jakarta.persistence.*;
import lombok.*;
import java.time.LocalDate;
import java.time.Period;

@Entity
@Table(name = "student")
@Getter @Setter
@NoArgsConstructor          // Hibernate 필수 — 기본 생성자
@AllArgsConstructor
public class StudentEntity {

    @Id
    @SequenceGenerator(
        name = "studentSeq",
        sequenceName = "STUDENT_SEQ",
        allocationSize = 1
    )
    @GeneratedValue(strategy = GenerationType.SEQUENCE,
                    generator = "studentSeq")
    private Long seq;

    @Column(nullable = false, length = 50)
    private String name;

    private LocalDate birthDate;

    @Transient          // DB 컬럼 생성 제외
    private int age;

    public int getAge() {
        if (birthDate == null) return 0;
        return Period.between(birthDate, LocalDate.now())
                     .getYears();
    }
}
```

## 한눈에 정리

| JPA 레이어 | 역할 | 구현 |
|---|---|---|
| Spring Data JPA | Repository 인터페이스 자동 구현 | `JpaRepository<E, ID>` 상속 |
| JPA API | ORM 표준 명세 | `EntityManager` (규격만) |
| Hibernate | JPA 구현체 + SQL 자동 생성 | spring-boot-starter-data-jpa 포함 |
| JDBC | DB 연결 표준 | 내부적으로 Hibernate가 사용 |

| 어노테이션 | 위치 | 역할 |
|---|---|---|
| `@Entity` | 클래스 | JPA 관리 대상 선언 |
| `@Table(name="...")` | 클래스 | 테이블명 명시 |
| `@Id` | 필드 | PK 컬럼 지정 |
| `@SequenceGenerator` | 필드 | 시퀀스 기반 PK 전략 정의 |
| `@GeneratedValue` | 필드 | PK 자동 생성 전략 연결 |
| `@Column` | 필드 | 컬럼 세부 제약 (nullable, length 등) |
| `@Transient` | 필드 | DB 컬럼 제외 (계산 전용) |

| ddl-auto | 시작 | 종료 | 사용 |
|---|---|---|---|
| `none` | 없음 | 없음 | 운영 |
| `create-drop` | DROP+CREATE | DROP | 로컬 테스트 |
| `create` | DROP+CREATE | 없음 | 거의 미사용 |
| `update` | 변경 반영 | 없음 | 개발 |
| `validate` | 스키마 검증 | 없음 | 마이그레이션 점검 |
