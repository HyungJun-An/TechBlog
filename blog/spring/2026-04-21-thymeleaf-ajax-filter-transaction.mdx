export function FetchFlowViz() {

  const [success, setSuccess] = useState(true);
  const [running, setRunning] = useState(false);
  const timerRef = useRef(null);

  const successSteps = [

## Thymeleaf 바인딩 문법 완전 정리

타임리프는 HTML 속성(`th:*`)으로 서버 값을 주입합니다. JSP의 EL/JSTL과 역할은 같지만 "HTML 형태를 유지"한다는 점이 핵심입니다.

<ThymeleafSyntaxDemo />

### 포인트 정리

| 상황 | 올바른 문법 | 잘못된 접근 |
|---|---|---|
| 태그 내용 출력 | `th:text="${vo.ename}"` | 태그 안에 EL 직접 삽입 |
| 빈 요소 값 | `th:value="${vo.empno}"` | `th:text` 적용 시 렌더링 안 됨 |
| URL 생성 | `th:href="@{/path(key=${val})}"` | 쿼리스트링 직접 문자열 조합 |
| 커스텀 데이터 | `th:attr="data-id=${vo.id}"` | `onclick="fn(${vo.id})"` 직접 주입 |

> `onclick="fn('[[${vo.ename}]]')"` 처럼 문자열을 JS 함수 인자로 직접 주입하면 특수문자 처리가 복잡합니다. `data-*` 속성에 값을 심고 `this.getAttribute()`로 읽는 패턴을 권장합니다.

## fetch 기반 AJAX와 @ResponseBody

### 서버: 뷰 리졸버를 타지 않는 직접 반환

```java
// @ResponseBody → 뷰 이름이 아닌 값 자체를 HTTP 응답 바디에 씁니다
@ResponseBody
@PostMapping("/emp/ajax")
public String ajax(@RequestParam("empno") String empno) {
    return empno + "님 반갑습니다.";
}

// 클래스 전체에 적용하려면 @RestController
// = @Controller + @ResponseBody
@RestController
public class EmpApiController { ... }
```

> **면접 포인트**: `@ResponseBody`는 내부적으로 `HttpServletResponse`의 `PrintWriter`로 값을 직접 출력합니다. 뷰 리졸버를 거치지 않습니다.

### 클라이언트: fetch 요청 흐름

아래 시뮬레이터로 성공/실패 흐름을 직접 확인해보세요.

<FetchFlowViz />

```js
function sendEmp(empno) {
  fetch('/emp/ajax', {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: 'empno=' + empno
  })
  .then(response => {
    // 200~299가 아니면 response.ok === false
    if (!response.ok) throw new Error('서버 오류: ' + response.status);
    return response.text();
  })
  .then(data => {
    document.getElementById('result').innerHTML = data;
  })
  .catch(error => console.log('에러:', error));
}
```

### MIME 타입 선택 기준

| MIME 타입 | 언제 사용 | 서버 바인딩 |
|---|---|---|
| `application/x-www-form-urlencoded` | 일반 파라미터 전송 | `@RequestParam` |
| `application/json` | 객체 구조 전송 | `@RequestBody` |
| `multipart/form-data` | 파일 업로드 포함 | `@RequestPart` |

## @Transactional 트랜잭션과 강제 롤백

### 핵심 개념

트랜잭션은 여러 DB 작업을 "전부 성공 또는 전부 실패"로 묶는 메커니즘입니다.

| 항목 | 내용 |
|---|---|
| 전파 기본값 | `Propagation.REQUIRED` — 기존 트랜잭션 참여, 없으면 새로 시작 |
| 롤백 트리거 | 예외 발생 (`RuntimeException`은 기본 롤백, 체크 예외는 `rollbackFor` 명시) |
| DB 오류만으론 부족 | 앱 레벨 실패(영향 row = 0)도 `throw`로 알려야 트랜잭션 매니저가 롤백 |

### 트랜잭션 흐름 시뮬레이터

토글을 켜면 INSERT 시점에 강제 예외를 발생시켜 롤백이 어떻게 동작하는지 확인할 수 있습니다.

<TransactionDemo />

```java
@Transactional(rollbackFor = Exception.class)
public void updateAndInsert(JobVO vo) throws Exception {
    int n = jobMapper.updateJob(vo);

    // DB 오류가 없어도 0건이면 실패로 간주 → throw로 롤백 유도
    if (n == 0) throw new Exception("update 실패: 대상 row 없음");

    int m = jobMapper.insertJob(vo);
    if (m == 0) throw new Exception("insert 실패");
}
```

> `@Transactional`이 없으면 UPDATE가 성공해도 INSERT가 실패할 때 이미 실행된 UPDATE는 그대로 남습니다.

## MyBatis + MVC 계층 분리

```
Controller  ← 요청 URL 매핑, 모델 담기, 뷰 이름 반환
    ↓ @Autowired
Service     ← 매퍼 조합, 트랜잭션 경계(@Transactional)
    ↓ @Autowired
Mapper(@Mapper) ← SQL 실행 단위 (XML id = 인터페이스 메소드명)
```

**AOP로 매퍼 공통 로깅:**

```java
@Aspect @Component
public class MapperLoggingAspect {

    @Pointcut("execution(* com.min.edu.mapper..*.*(..))")
    public void mapperMethods() {}

    @Before("mapperMethods()")
    public void logBefore(JoinPoint jp) {
        log.info("[매퍼 호출] {} / args={}", jp.getSignature().getName(),
                 Arrays.toString(jp.getArgs()));
    }

    @AfterThrowing(pointcut = "mapperMethods()", throwing = "e")
    public void logException(Exception e) {
        log.error("[매퍼 예외] {}", e.getMessage());
    }
}
```

## @WebFilter 웹 필터 — 접속 로그

```java
@WebFilter(urlPatterns = "/*")   // 모든 요청을 가로챕니다
public class AccessLogFilter implements Filter {

    @Override
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {

        HttpServletRequest request = (HttpServletRequest) req;

        String ip    = request.getRemoteAddr();
        String url   = request.getRequestURL().toString();
        String query = request.getQueryString();           // ?empno=7839 부분

        StringBuilder sb = new StringBuilder();
        sb.append("[접속] IP=").append(ip)
          .append(" | URL=").append(url);

        // 쿼리스트링이 없으면 null → StringUtils로 안전하게 처리
        if (StringUtils.isNotEmpty(query)) {
            sb.append("?").append(query);
        }

        log.info(sb.toString());
        chain.doFilter(req, res);   // 반드시 호출 — 다음 단계로 흐름 전달
    }
}
```

| 수집 항목 | API | 의미 |
|---|---|---|
| 원격 IP | `getRemoteAddr()` | 요청 클라이언트 주소 |
| 전체 URL | `getRequestURL().toString()` | 프로토콜 포함 |
| 쿼리스트링 | `getQueryString()` | `?` 뒤 파라미터 원문, 없으면 `null` |

> 실무 활용: 반복 요청 봇 IP 차단, 내부망 IP 외 접근 차단, PV/유입 경로 분석

## @ControllerAdvice 전역 예외 처리

컨트롤러마다 `try-catch`를 반복하지 않고 전역 처리기 하나로 모든 예외를 처리합니다.

```java
@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public String handleException(Exception e, Model model) {
        model.addAttribute("message", e.getMessage());
        model.addAttribute("status",  500);
        return "error/error";   // templates/error/error.html 로 이동
    }
}
```

```html
<!-- templates/error/error.html -->
<h2>오류가 발생했습니다</h2>
<p th:text="${message}">오류 메시지</p>
<button onclick="history.go(-1)">이전으로</button>
```

> REST API 프로젝트라면 뷰 이름 반환 대신 `@ExceptionHandler` + `ResponseEntity<ErrorResponse>` 조합으로 JSON 에러 바디를 반환합니다.

## 한눈에 정리

| 기술 | 핵심 포인트 |
|---|---|
| **Thymeleaf 문법** | 콘텐츠 출력 → `th:text`, 속성값 → `th:value`, JS 값 전달 → `data-*` + `getAttribute` |
| **fetch AJAX** | `response.ok` 체크 → `throw` → `.catch()` 템플릿 고정, MIME 타입 일치 필수 |
| **@ResponseBody** | 뷰 리졸버를 거치지 않고 응답 바디에 직접 씀, `@RestController = @Controller + @ResponseBody` |
| **@Transactional** | DB 오류뿐 아니라 앱 레벨 실패도 `throw`로 알려야 롤백, 기본 전파는 `REQUIRED` |
| **@WebFilter** | `chain.doFilter()` 호출 누락 시 요청이 중단됨, 쿼리스트링은 `null` 체크 필수 |
| **@ControllerAdvice** | 전역 예외 한 곳 처리, REST면 `ResponseEntity`, MVC면 뷰 이름 반환 |
