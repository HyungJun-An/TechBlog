## DOM 탐색 완전 정리

게시판 관리 화면에서 "복구" 버튼을 클릭해 해당 행의 SEQ를 추출하고 tr을 제거하는 흐름이 DOM 탐색의 집약입니다. 아래 컴포넌트에서 각 탐색 방법을 직접 확인하세요.

<DOMTraversalExplorer />

### getElementById vs querySelector — 언제 뭘 쓸까

| 방법 | 탐색 기준 | 반환 | 특징 |
|---|---|---|---|
| `getElementById("id")` | id 속성 | Element or null | 가장 빠름, id는 문서에서 유일해야 합니다. |
| `getElementsByName("name")` | name 속성 | HTMLCollection | `<input name="chk">` 같은 다중 요소 탐색 시 사용합니다. |
| `getElementsByClassName("cls")` | class 속성 | HTMLCollection | 동적으로 변경되지만 NodeList보다 느립니다. |
| `querySelector("CSS선택자")` | CSS 선택자 | Element or null | 가장 유연함, 첫 번째 일치 요소만 반환합니다. |
| `querySelectorAll("CSS선택자")` | CSS 선택자 | NodeList(정적) | 일치하는 전체 반환, 스냅샷이므로 DOM 변경 반영 안 됩니다. |
| `closest("CSS선택자")` | 조상 탐색 | Element or null | 자신부터 위로 올라가며 탐색합니다. |

```javascript
// ✅ 실무 패턴 — 체크박스 다중 선택 + SEQ 추출
document.querySelector("button.deleteAll")
  .addEventListener("click", function() {
    // 1. 체크된 항목 탐색
    const checked = document.querySelectorAll(
      "input[type='checkbox'][name='chkVal']:checked"
    );
    if (checked.length === 0) {
      alert("삭제할 항목을 선택하세요."); return;
    }

    // 2. SEQ 값 수집
    const seqs = [...checked].map(cb =>
      cb.closest("tr").children[0].textContent.trim()
    );

    // 3. URLSearchParams로 묶어 전송
    const params = new URLSearchParams();
    seqs.forEach(seq => params.append("chkVal", seq));
    location.href = "/multiDelete?" + params.toString();
  });
```

> `getElementsByName`이 반환하는 `HTMLCollection`은 for-of나 `[...spread]`로 순회할 수 있지만, `querySelectorAll`의 `NodeList`가 `forEach`를 직접 지원해 더 편리합니다.

## @RestController와 Jackson 직렬화 흐름

`@RestController`가 붙으면 메서드 반환값은 ViewResolver가 아닌 `HttpMessageConverter`로 전달됩니다. Spring Boot는 Jackson을 기본 컨버터로 등록해 Java 객체를 JSON으로 자동 직렬화합니다.

<JacksonFlowViz />

### @Controller vs @RestController 구조 비교

```java
// @Controller: 반환값 → ViewResolver → 템플릿 렌더링
@Controller
public class BoardController {

    @GetMapping("/board/list")
    public String list(Model model) {
        model.addAttribute("boards", boardService.getAll());
        return "board/list";  // → templates/board/list.html
    }

    // 특정 메서드만 JSON 반환 시 @ResponseBody 추가
    @GetMapping("/board/count")
    @ResponseBody
    public int count() {
        return boardService.count();  // → 42
    }
}

// @RestController = @Controller + @ResponseBody (클래스 전체)
@RestController
@RequestMapping("/api/board")
public class BoardApiController {

    @GetMapping
    public List<BoardVO> list() {
        return boardService.getAll();
        // → [{"seq":1,"title":"..."},{"seq":2,...}]
    }

    @GetMapping("/{seq}")
    public ResponseEntity<BoardVO> detail(@PathVariable int seq) {
        BoardVO vo = boardService.getOne(seq);
        if (vo == null) return ResponseEntity.notFound().build();
        return ResponseEntity.ok(vo);
    }
}
```

### ApiResponse 래퍼 — 표준화된 응답 구조

실무에서는 Jackson 직렬화 결과를 공통 래퍼로 감싸 일관된 응답 구조를 만듭니다.

```java
// 공통 응답 래퍼
public class ApiResponse<T> {
    private boolean success;
    private String message;
    private T data;

    public static <T> ApiResponse<T> ok(T data) {
        ApiResponse<T> r = new ApiResponse<>();
        r.success = true;
        r.data = data;
        return r;
    }

    public static ApiResponse<Void> fail(String msg) {
        ApiResponse<Void> r = new ApiResponse<>();
        r.success = false;
        r.message = msg;
        return r;
    }
}

// 컨트롤러 적용
@GetMapping("/user/{id}")
public ApiResponse<UserVO> getUser(@PathVariable String id) {
    UserVO user = userService.findById(id);
    return user != null
        ? ApiResponse.ok(user)
        : ApiResponse.fail("사용자를 찾을 수 없습니다.");
}
// → {"success":true,"message":null,"data":{"id":"user01",...}}
// → {"success":false,"message":"사용자를 찾을 수 없습니다.","data":null}
```

```javascript
fetch("/user/user01")
  .then(res => res.json())
  .then(({ success, message, data }) => {
    if (!success) { alert(message); return; }

  });
```

## 데이터 전송 방식 완전 비교 — FormData · URLSearchParams · JSON Body

HTTP 요청 바디에 데이터를 담는 방법은 세 가지입니다. Content-Type 헤더가 서버의 파싱 방식을 결정합니다.

<DataTransmitCompare />

### FormData 핵심 주의점

```javascript
// ⚠️ FormData 사용 시 Content-Type 헤더를 직접 지정하면 안 됩니다
fetch("/upload", {
  method: "POST",
  // ❌ 잘못된 방식 — boundary가 없어 서버 파싱 실패
  headers: { "Content-Type": "multipart/form-data" },
  body: fd
});

// ✅ 올바른 방식 — headers 생략, 브라우저가 자동 설정
fetch("/upload", {
  method: "POST",
  body: fd  // Content-Type: multipart/form-data; boundary=----WebKitFormBoundary...
});
```

> multipart/form-data는 데이터 경계를 나타내는 `boundary` 값이 Content-Type 헤더에 포함되어야 합니다. 브라우저가 FormData를 감지하면 boundary를 자동 생성해 헤더에 추가하므로, 헤더를 직접 지정하면 boundary가 빠져 서버에서 파싱에 실패합니다.

### 한 요청에 파일 + JSON 함께 보내기

```javascript
// FormData + JSON 혼합 전송
const fd = new FormData();
fd.append("file", fileInput.files[0]);
// JSON을 문자열로 변환 후 Blob으로 추가
fd.append("meta", new Blob(
  [JSON.stringify({ title: "제목", tags: ["java"] })],
  { type: "application/json" }
));

fetch("/board/upload", { method: "POST", body: fd });
```

```java
// 서버: @RequestPart로 혼합 수신
@PostMapping("/board/upload")
public ResponseEntity<BoardVO> upload(
        @RequestParam MultipartFile file,
        @RequestPart("meta") BoardMetaDTO meta) {
    // meta: JSON이 DTO로 자동 변환
    return ResponseEntity.ok(boardService.save(file, meta));
}
```

## 한눈에 정리

| 항목 | URLSearchParams | FormData | JSON Body |
|---|---|---|---|
| **Content-Type** | application/x-www-form-urlencoded | multipart/form-data (자동) | application/json |
| **파일 전송** | 불가 | 가능 | 불가 |
| **중첩 구조** | 불가 | 불가 | 가능 |
| **서버 어노테이션** | @RequestParam, @ModelAttribute | @RequestParam MultipartFile | @RequestBody |
| **클라이언트** | `new URLSearchParams()` | `new FormData()` | `JSON.stringify()` |
| **주의사항** | Content-Type 헤더 직접 지정 | 헤더 지정 금지! | Content-Type: application/json 필수 |

| DOM 탐색 | 용도 | 반환 |
|---|---|---|
| `querySelector` | CSS 선택자, 첫 번째 요소 | Element or null |
| `querySelectorAll` | CSS 선택자, 전체 | NodeList |
| `closest("tr")` | 조상 탐색 (SPA 패턴 핵심) | Element or null |
| `children[0]` | 자식 Element (인덱스) | Element |
| `.textContent` | 순수 텍스트 추출 | String |
| `tr.remove()` | DOM 노드 삭제 (리프레시 없음) | void |

| Jackson | 설명 |
|---|---|
| `@RestController` | @Controller + @ResponseBody, 전체 메서드가 JSON 반환 |
| `@ResponseBody` | 개별 메서드의 반환값을 HTTP 바디로 직렬화 |
| `@JsonIgnore` | 해당 필드를 직렬화/역직렬화에서 제외 |
| `@JsonProperty` | JSON 키 이름 재정의 (camelCase ↔ snake_case) |
| `ObjectMapper` | Jackson의 핵심 클래스, Java ↔ JSON 변환 담당 |
