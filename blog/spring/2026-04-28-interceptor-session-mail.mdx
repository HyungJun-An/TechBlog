                             Object handler) throws Exception {

        HttpSession session = req.getSession(false);
        // 세션 없거나 로그인 VO 없으면 차단

                  {s.label}
                </span>
                {isPreHandle && (active || done) && (
                  <span style={{ fontSize: 10, padding: '2px 7px', borderRadius: 10, background: '#fef3c7', color: '#d97706', fontWeight: 700 }}>
                    false → 차단
                  </span>
                )}
              </div>
              {active && (
                <div style={{ margin: '4px 0 4px 34px', padding: '6px 10px', borderRadius: 6,
                  background: s.color + '10', borderLeft: `3px solid ${s.color}`, fontSize: 11, color: 'var(--ifm-color-secondary-darkest)', lineHeight: 1.6 }}>
                  {s.note}
                </div>
              )}
            </div>
          );
        })}
      </div>

      {/* 인터셉터 구현 탭 */}
      <div style={{ background: 'var(--ifm-color-emphasis-100)', borderBottom: '1px solid var(--ifm-color-emphasis-200)' }}>
        <div style={{ padding: '10px 14px 0', fontSize: 11, fontWeight: 700, color: '#6b7280', marginBottom: 4 }}>인터셉터 구현 코드:</div>
        <div style={{ display: 'flex' }}>
          {tabs.map(t => (
            <button key={t.id} onClick={() => setActiveTab(t.id)}
              style={{ padding: '8px 14px', border: 'none', borderBottom: activeTab === t.id ? `3px solid ${t.color}` : '3px solid transparent',
                background: 'none', color: activeTab === t.id ? t.color : 'var(--ifm-color-secondary-darkest)',
                fontWeight: activeTab === t.id ? 700 : 400, cursor: 'pointer', fontSize: 12, whiteSpace: 'nowrap' }}>
              {t.label}
            </button>
          ))}
        </div>

## Interceptor와 WebMvcConfigurer

Filter가 서블릿 컨테이너 수준에서 요청을 가로챈다면, Interceptor는 스프링 컨테이너 안에서 컨트롤러 진입 전후를 세밀하게 제어합니다.

<InterceptorFlowViz />

### Filter vs Interceptor 역할 분담

| 구분 | Filter | Interceptor |
|---|---|---|
| **동작 위치** | 서블릿 컨테이너 (스프링 밖) | 스프링 MVC (DispatcherServlet 이후) |
| **스프링 빈 주입** | 제한적 | 자유롭게 사용 가능 |
| **요청 데이터 접근** | 원시 `ServletRequest` | `HandlerMethod` — 어떤 컨트롤러·메서드인지까지 파악 |
| **적합한 용도** | 인코딩 설정, 공통 로깅, XSS 필터 | 로그인 인증, 권한 체크, 캐시 제어, 응답 가공 |
| **예외 처리** | `@ControllerAdvice` 미적용 | `@ControllerAdvice` 적용 가능 |

```java
// HandlerMethod 캐스팅으로 어노테이션 기반 인증 제어도 가능
public boolean preHandle(HttpServletRequest req,
                         HttpServletResponse res,
                         Object handler) {
    if (handler instanceof HandlerMethod hm) {
        // 특정 어노테이션이 있는 메서드만 인증 통과
        if (hm.hasMethodAnnotation(PermitAll.class)) return true;
    }
    // 세션 체크 로직...
}
```

## HttpSession vs @SessionAttributes

두 세션의 차이는 생성 방식보다 **삭제 스코프와 컨트롤러 종속성**에 있습니다.

<SessionCompare />

### 실무 사용 기준 요약

| 상황 | 선택 | 이유 |
|---|---|---|
| 로그인 상태·권한 | `HttpSession` | 인터셉터 포함 전역 접근이 필요합니다. |
| 멀티스텝 폼 (주문·회원가입 단계) | `@SessionAttributes` | 흐름 종료 시 `setComplete()`로 깔끔하게 정리합니다. |
| 장바구니 임시 저장 | `@SessionAttributes` | 특정 컨트롤러 흐름에 종속되어 범위 제어가 용이합니다. |
| 전체 로그아웃 | `HttpSession.invalidate()` | 세션 전체를 한 번에 정리해야 일관성이 유지됩니다. |

## @ModelAttribute — 두 가지 의미

`@ModelAttribute`는 두 가지 전혀 다른 역할을 합니다. 이 두 가지를 구분하지 않으면 "코드에 없는데 모델에 값이 있다"는 혼란이 생깁니다.

```java
// 의미 1 — 요청 파라미터 → DTO 자동 바인딩 (생략 가능)
@PostMapping("/login")
public String login(@ModelAttribute UserVO vo) {
    // 폼 파라미터 id, pw가 vo.id, vo.pw로 자동 매핑됨
    // @ModelAttribute는 생략해도 동일하게 동작
}
```

```java
// 의미 2 — 컨트롤러 실행 전 모델에 참조 데이터 자동 주입
@Controller
@RequestMapping("/user")
public class UserController {

    // 이 컨트롤러의 모든 요청 처리 전에 먼저 실행됨
    @ModelAttribute("userTypes")
    public List<String> referenceUserTypes() {
        return List.of("ADMIN", "USER", "GUEST");
    }

    // model.addAttribute("userTypes", ...) 없이도
    // 뷰에서 ${userTypes}로 바로 출력 가능
    @GetMapping("/form")
    public String form() {
        return "user/form";
    }
}
```

```html
<!-- 뷰 — 별도 addAttribute 없이 자동으로 참조 가능 -->
<select name="role">
  <option th:each="t : ${userTypes}" th:value="${t}" th:text="${t}"></option>
</select>
```

> 유지보수 시 "이 값이 어디서 왔는지" 추적이 어려울 수 있습니다. 팀 프로젝트라면 `@ModelAttribute` 메서드가 있음을 명시적으로 주석으로 남기거나 별도 클래스로 분리하는 것이 좋습니다.

## SMTP 메일 전송 — JavaMailSender

메일 서버를 직접 구축하는 것이 아니라, **Gmail 같은 외부 SMTP 서버를 통해 프로젝트에서 메일을 발송**하는 구조입니다. 알림 메일, 인증 메일, AI 에이전트 결과 발송 등 실무에서 자주 사용됩니다.

<MailFlowViz />

### Gmail 앱 비밀번호 발급 순서

```
Google 계정 → 보안 → 2단계 인증 활성화
→ 앱 비밀번호 → 앱 선택: 메일 / 기기: Windows 컴퓨터
→ 16자리 앱 키 생성 → application.properties에 입력
```

> 앱 비밀번호는 계정의 2단계 인증이 활성화된 경우에만 발급됩니다. 실제 계정 비밀번호를 properties에 넣으면 Gmail 보안 정책으로 인증이 거부됩니다.

### 메일 발송 실패 원인 체크리스트

| 증상 | 원인 | 해결 |
|---|---|---|
| `AuthenticationFailedException` | 앱 비밀번호가 아닌 계정 PW 사용 | Gmail 앱 비밀번호 발급 후 교체 |
| `Connection timed out` | TLS 설정 누락 | `starttls.enable=true` 추가 |
| 제목·본문 한글 깨짐 | 인코딩 미지정 | `new MimeMessageHelper(msg, true, "UTF-8")` |
| 첨부파일 없이 MimeMessageHelper 오류 | 멀티파트 미활성화 | 생성자 두 번째 인자 `true` |
| 스팸 처리 | 빈 제목 또는 빈 본문 | 제목·본문 반드시 작성 |

## 한눈에 정리

| Interceptor | 실행 시점 | 용도 |
|---|---|---|
| `preHandle` | 컨트롤러 실행 전 | 로그인 체크, `false` 반환으로 차단 |
| `postHandle` | 컨트롤러 후, 뷰 렌더링 전 | 캐시 헤더, 응답 가공 |
| `afterCompletion` | 뷰 렌더링 완료 후 | 리소스 정리, 로깅 마무리 |

| 세션 | 삭제 방법 | 범위 |
|---|---|---|
| `HttpSession` | `invalidate()` / `removeAttribute()` | 애플리케이션 전역 |
| `@SessionAttributes` | `SessionStatus.setComplete()` | 선언한 컨트롤러 한정 |

| 메일 설정 | 값 | 설명 |
|---|---|---|
| `spring.mail.host` | `smtp.gmail.com` | SMTP 서버 |
| `spring.mail.port` | `587` | TLS 포트 |
| `spring.mail.password` | 앱 비밀번호 16자리 | 계정 PW가 아닌 앱 키 |
| `setText(content, true)` | `true` | HTML 렌더링 활성화 |
