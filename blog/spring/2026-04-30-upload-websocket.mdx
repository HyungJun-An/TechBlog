export function AjaxUploadDemo() {
  const [files, setFiles] = useState([]);
  const [errors, setErrors] = useState([]);
  const [activeTab, setActiveTab] = useState('validate');
  const MAX_SIZE = 5 * 1024 * 1024;
  const ALLOWED = /\.(jpg|jpeg|png|bmp|gif)$/i;

  const handleFileChange = (e) => {
    const selected = Array.from(e.target.files);
    const newFiles = [];
    const newErrors = [];
    selected.forEach(f => {
      if (!ALLOWED.test(f.name)) {
        newErrors.push(`${f.name} — 허용되지 않는 확장자`);
      } else if (f.size > MAX_SIZE) {
        newErrors.push(`${f.name} — 5MB 초과 (${(f.size/1024/1024).toFixed(1)}MB)`);
      } else {
        newFiles.push({ name: f.name, size: f.size, url: URL.createObjectURL(f) });
      }
    });
    setFiles(prev => [...prev, ...newFiles]);
    setErrors(newErrors);
    e.target.value = '';
  };

  const remove = (idx) => setFiles(prev => prev.filter((_, i) => i !== idx));

  const tabs = [
    {
      id: 'validate',
      label: '유효성 검사',

```java
file.transferTo(new File(savePath + saved));
```

> **getRealPath() 주의**: 개발 환경에서는 편하지만, 외장 서버(jar 배포, 도커 컨테이너) 환경에서는 경로가 달라지거나 재시작 시 파일이 사라질 수 있습니다. 운영에서는 `@Value`로 주입하는 절대 경로 또는 S3/NAS 같은 외부 스토리지를 사용하세요.

## 파일 다운로드 — 응답 헤더 설정

```java
@GetMapping("/download.2")
@ResponseBody
public byte[] download(
        @RequestParam String saved,
        @RequestParam String origin,
        HttpServletRequest req,
        HttpServletResponse res) throws Exception {

    String savePath = req.getServletContext()
                        .getRealPath("/upload/");
    File file = new File(savePath + saved);

    // 다운로드 강제: attachment + 파일명 지정
    // 한글 파일명 깨짐 방지: ISO-8859-1 인코딩
    String encodedName = new String(
        origin.getBytes("UTF-8"), "8859_1");
    res.setHeader("Content-Disposition",
        "attachment; filename=\"" + encodedName + "\"");

    // 범용 바이너리 — 특정 타입(PDF 등)은 명시 가능
    res.setContentType("application/octet-stream");

    // 다운로드 진행률 표시를 위해 크기 지정
    byte[] bytes = FileCopyUtils.copyToByteArray(file);
    res.setContentLength(bytes.length);

    return bytes;
}
```

| 헤더 | 값 | 목적 |
|---|---|---|
| `Content-Disposition` | `attachment; filename="..."` | 브라우저에 파일로 저장하도록 지시 |
| `Content-Type` | `application/octet-stream` | 범용 바이너리 (브라우저가 실행하지 않음) |
| `Content-Length` | `bytes.length` | 다운로드 진행률 바 표시 가능 |

> `inline`으로 지정하면 브라우저가 PDF·이미지를 다운로드 대신 화면에 표시합니다. 강제 다운로드가 목적이라면 반드시 `attachment`를 사용하세요.

## Spring WebSocket 기술 스택

MIME 타입과 WebSocket의 관계, 그리고 Spring에서 제공하는 방식들을 정리합니다.

### WebSocket 핸드셰이크와 MIME

WebSocket 연결은 HTTP Upgrade 요청으로 시작합니다. 일반 HTTP 요청이 아니므로 HTML/JSON처럼 Content-Type(MIME 타입)이 응답 바디에 없지만, **핸드셰이크 시 `Sec-WebSocket-Protocol` 헤더로 서브 프로토콜을 협상**합니다.

```
Client → Server (HTTP Upgrade 요청)
GET /ws/chat HTTP/1.1
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
Sec-WebSocket-Version: 13
Sec-WebSocket-Protocol: stomp, chat  ← 서브 프로토콜 협상

Server → Client (101 Switching Protocols)
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: ...
Sec-WebSocket-Protocol: stomp       ← 선택된 프로토콜
```

핸드셰이크 이후 연결이 전환되면 HTTP가 아닌 **WebSocket 프레임** 단위로 통신합니다. 이때 메시지 내용이 텍스트인지 바이너리인지를 프레임 타입(opcode)으로 구분합니다.

## 순수 TextWebSocketHandler 1:N 채팅 실습

STOMP 없이 순수 WebSocket만으로 채팅을 구성했습니다. 세션 목록 직접 관리, 프리픽스 기반 메시지 분기가 핵심입니다.

<ChatDemo />

### 핸들러 계층 구조

```
WebSocketHandler  ← 최상위 인터페이스
  └── AbstractWebSocketHandler  ← 공통 기반 (텍스트+바이너리)
        ├── TextWebSocketHandler   ← 텍스트 메시지 처리 (오늘 실습)
        └── BinaryWebSocketHandler ← 바이너리 데이터 처리 (이미지·음성)
```

| 클래스 | 오버라이드 대상 | 용도 |
|---|---|---|
| `TextWebSocketHandler` | `handleTextMessage()` | 문자 기반 채팅, JSON 명령 처리 |
| `BinaryWebSocketHandler` | `handleBinaryMessage()` | 파일·이미지·음성 스트리밍 |
| `AbstractWebSocketHandler` | 둘 다 | 텍스트·바이너리 혼용 |

### getPayload() vs toString() 차이

```java
// TextMessage가 수신됐을 때
TextMessage message = ...; // "안녕하세요"

message.getPayload()  // → "안녕하세요"  ← 실제 내용만 추출
message.toString()    // → "TextMessage payload=[안녕하세요], last=true"
                      //    래퍼 정보가 포함되어 직접 쓰면 의도치 않은 문자 포함
```

### 프리픽스 기반 메시지 분기

수업에서는 `#$nick`이라는 특수 프리픽스로 닉네임 등록과 일반 채팅을 구분했습니다.

```java
if (payload.contains("#$nick")) {
    // 닉네임 등록 처리
    String nick = payload.replace("#$nick", "");
    nickMap.put(session, nick);
    broadcast(nick + "님이 입장했습니다.", session, true);
} else if (payload.contains("!ALERT")) {
    // 알림 메시지 분기
    handleAlert(payload, session);
} else {
    // 일반 채팅 메시지
    String nick = nickMap.getOrDefault(session, "익명");
    broadcast("<b>" + nick + "</b>: " + payload, null, false);
}
```

> 프리픽스 방식은 단순하지만 특수문자 충돌 위험이 있습니다. 확장성이 필요하면 JSON 메시지 모델(`{"type":"CHAT","payload":"..."}`)로 발전시키는 것이 좋습니다. STOMP를 쓰면 이 분기 처리 자체가 `@MessageMapping` 라우팅으로 자동화됩니다.
