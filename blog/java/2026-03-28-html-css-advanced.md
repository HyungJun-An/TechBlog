### **1. div와 영역 분할 — 왜 나누는가**

`div`는 시맨틱 의미가 없는 영역 태그로, 화면을 구획으로 나눠 DOM 탐색과 CSS 선택을 쉽게 하기 위해 사용합니다. 주소 체계처럼 "어디의 무엇"을 빠르게 찾기 위한 구조화가 핵심입니다.

| 태그 | 의미 유무 | 주요 용도 |
| :--- | :--- | :--- |
| `div` | 없음 | 레이아웃 구획, 선택자 설계 |
| `section` | 있음 | 독립적인 콘텐츠 구획 |
| `aside` | 있음 | 보조 정보 (사이드바 등) |
| `nav` | 있음 | 탐색 메뉴 |
| `thead` / `tbody` | 있음 | 테이블 구조 분해 |

- 영역을 나눠두면 이후 CSS/JS에서 특정 엘리먼트를 선택하고 제어하기 쉬워집니다.
- 블록 요소(`div`, `p`, `h1` 등)는 한 줄 전체를 차지하는 흐름을 만들고, 인라인 요소(`span`, `a`, `img` 등)는 콘텐츠 크기만큼만 영역을 차지합니다.
- 블록 요소 안에 또 다른 블록을 무분별하게 중첩하면 구조가 어색해질 수 있으니 의도를 분명히 해야 합니다.

### **2. 링크 · 이미지 · 목록 태그**

**`a` 태그 — 이동 흐름 제어**

| 속성 | 설명 |
| :--- | :--- |
| `href="#id"` | 현재 문서 내 해당 `id` 위치로 스크롤 이동 (앵커) |
| `target="_blank"` | 새 탭으로 열기 (팝업과 구분) |
| `title` | 툴팁 + 스크린 리더가 읽는 접근성 정보 |

- `href="#"`는 단순한 주소 대체가 아니라 문서 내 `id`를 지칭하는 앵커 이동입니다.
- 링크 텍스트와 `title`은 사용자, 보조기기 모두가 이해 가능한 설명으로 작성하는 것이 바람직합니다.

**`<img>` vs `background-image`**

| 방식 | 적합 용도 | 특징 |
| :--- | :--- | :--- |
| `<img src="...">` | 콘텐츠 이미지 (의미 있는 이미지) | `alt` 필수, 사용자가 저장/복사 가능 |
| `background-image` | 장식/배경 이미지 | 직접 선택 어려움, CSS 파일 위치 기준 상대 경로 |

**목록 태그**

```html
<ul>  <!-- 순서 없음, 불릿 -->
    <li>항목 A</li>
    <li>항목 B</li>
</ul>

<ol>  <!-- 순서 있음, 번호 -->
    <li>1단계</li>
    <li>2단계</li>
</ol>
```

목록의 마커 모양 변경은 CSS `list-style`로 제어하는 방식이 일반적입니다.

**날짜 + 인라인 이벤트**

```html
<h2 onclick="alert('금요일이다')">클릭해 보세요</h2>
<time>2026-03-28</time>
```

`time` 태그는 플랫폼/보조기기에서 날짜로 인식하는 데 유리합니다. `onclick` 같은 인라인 이벤트 속성은 구조와 동작이 섞이므로, 규모가 커지면 JS 파일로 분리하는 방식을 권장합니다.

### **3. 외부 폰트 — Import vs Font-face**

| 구분 | 방식 | 특징 | 주의점 |
| :--- | :--- | :--- | :--- |
| Import | `@import url(...)` | 제공된 CSS를 그대로 가져와 빠르게 적용 | 폰트 패밀리명을 정확히 사용해야 함 |
| Font-face | `@font-face { ... }` | 폰트를 선언하고 필요한 것만 선택적으로 사용 | 이름에 따옴표 포함 여부 확인 필요 |

```css
/* Import 방식 */
@import url('https://fonts.googleapis.com/css2?family=Noto+Sans+KR');

body { font-family: 'Noto Sans KR', sans-serif; }

/* Font-face 방식 */
@font-face {
    font-family: 'MyFont';
    src: url('../fonts/myfont.woff2') format('woff2');
}
```

- **폰트를 먼저 확정하고 레이아웃을 잡는** 순서를 권장합니다. 폰트마다 자간·행간이 달라, 나중에 폰트를 바꾸면 레이아웃이 틀어질 수 있습니다.
- 폰트 패밀리 폴백은 "동시에 적용"이 아니라 **"없을 때 다음 폰트로 대체"** 입니다.
- 외부 폰트가 적용되지 않으면 개발자도구 Network 탭에서 폰트 CSS/리소스가 정상 로딩되는지 확인하고, 캐시 문제는 강력 새로고침(`Ctrl+Shift+R`)으로 점검합니다.
- 폰트는 **라이선스(상업적 사용 가능 여부)** 를 반드시 확인해야 합니다.

### **4. CSS 단위, 색상, 초기화 전략**

**CSS 초기화**

```css
* { margin: 0; padding: 0; }
```

브라우저 기본 스타일(예: `p`의 기본 여백)을 제거하고 "내가 정의한 기준"으로 일관되게 작업하기 위한 전략입니다. 초기화 후에는 필요한 여백을 의도적으로 다시 부여해야 합니다.

**크기 단위**

| 단위 | 기준 | 용도 요약 |
| :--- | :--- | :--- |
| `px` | 고정 | 정확한 고정 크기, 유동성 부족 |
| `em` | 부모 폰트 | 부모 기준 비례 조정, 컴포넌트 단위 |
| `rem` | 루트 폰트 | 전체 스케일을 일관되게 키우고 줄이기 |
| `%` | 부모 크기 | 컨테이너 대비 비율 기반 레이아웃 |
| `vw/vh` | 뷰포트 | 디바이스 크기 변화에 즉시 반응 |

특히 `rem`은 루트(`body`) 기준이므로 전체 일관성 유지에 유리합니다.

**색상 표기**

| 표기 | 예시 | 특징 |
| :--- | :--- | :--- |
| 이름 | `olive` | 간단하지만 제어 범위 제한 |
| RGB | `rgb(128, 128, 0)` | 채널 기반, 디자이너 협업에 자주 사용 |
| HEX | `#808000` | 코드에서 가장 흔하며 축약/재사용에 유리 |

### **5. 반응형 웹앱과 미디어 쿼리**

미디어 쿼리는 특정 폭 조건에서 CSS를 오버라이드하는 구조입니다. `@media` 문법의 공백(띄어쓰기) 누락으로 동작이 실패하는 사례가 많으니 문법 정확성에 주의합니다.

```css
/* 공통 CSS */
.container { width: 960px; }
.ad-box    { display: block; }

/* 태블릿 이하 */
@media (max-width: 768px) {
    .container { width: 100%; }
}

/* 모바일 */
@media (max-width: 480px) {
    .ad-box { display: none; }   /* 모바일에서 광고 숨김 */
    img     { width: 100%; }     /* 이미지 부모 폭에 맞춤 */
}
```

| 상황 | 처리 | 의미 |
| :--- | :--- | :--- |
| 모바일에서 광고 숨김 | `display: none` | 요소가 렌더링 흐름에서 제거됨 |
| 조건 만족 시 다시 표시 | `display: block` | UI 상태 제어 |
| 이미지 폭 확장 | `width: 100%` | 부모 폭 기준 유연하게 맞춤 |

- 공통 CSS 위에 미디어 쿼리로 단계별 오버라이드하는 방식이 유지보수에 유리합니다.
- 개발자도구 반응형 모드로 폭을 바꾸며 적용 여부를 검증합니다.

### **6. 선택자 종류 — 후손 vs 자식**

| 선택자 | 의미 | 적용 범위 |
| :--- | :--- | :--- |
| `A B` | A 내부의 모든 B (후손 선택자) | 깊은 중첩까지 포함 |
| `A > B` | A의 바로 아래 자식 B (자식 선택자) | 1단계 자식만 선택 |

```css
div img   { border: 1px solid red; }   /* div 안 모든 img */
div > img { border: 1px solid blue; }  /* div 바로 아래 img만 */
```

### **7. float · clear와 배경 이미지**

**float / clear**

`float`는 요소를 좌/우로 띄워 이후 요소가 흐르듯 배치되게 하는 전통적 레이아웃 기법입니다. float된 요소는 문서 흐름에서 일부 분리되므로 부모 높이 계산이 깨질 수 있습니다.

```css
.left-box  { float: left;  width: 200px; }
.right-box { float: right; width: 200px; }
.footer    { clear: both; }   /* float 침범 정리, 하단 영역 겹침 방지 */
```

**배경 이미지 경로 — CSS 파일 위치 기준**

중요한 실무 포인트: **상대 경로의 기준은 HTML이 아니라 CSS 파일 위치**입니다.

```
프로젝트 구조:
  /css/style.css
  /image/stamp.png
```

```css
/* CSS 파일이 /css/ 에 있으므로 ../로 상위 이동 */
#guarantee {
    background-image: url("../image/stamp.png");
    background-repeat: no-repeat;
    background-position: top right;
}

/* 여러 배경 겹치기 — 상단/하단 장식 바 */
#banner {
    background-image: url("../image/top-bar.png"), url("../image/bottom-bar.png");
    background-repeat: repeat-x, repeat-x;
    background-position: top, bottom;
}
```

### **8. 링크 상태, 텍스트 효과, 프로토타이핑 팁**

**링크 상태 스타일링**

앵커 태그는 기본적으로 밑줄과 방문색이 존재합니다. 실무에서는 초기화 후 상태별로 재정의하는 경우가 많습니다.

```css
a             { text-decoration: none; color: inherit; }  /* 기본 초기화 */
a:link        { color: #1a73e8; }          /* 미방문 링크 */
a:visited     { color: #1a73e8; }          /* 방문한 링크 — 보라색 방지 */
a:hover       { color: #0d47a1; text-decoration: underline; }
```

**text-shadow**

문법: `x이동 y이동 blur color`, 콤마로 여러 그림자를 중첩할 수 있습니다.

```css
h1 {
    text-shadow: 2px 2px 4px rgba(0,0,0,0.3),   /* 기본 그림자 */
                 0   0   8px rgba(0,0,0,0.1);    /* 퍼짐 효과 */
}
```

**프로토타이핑 — placeholder 이미지**

실제 이미지를 아직 받지 못했더라도 크기 박스를 먼저 잡고 이후 교체하면 레이아웃 설계가 쉬워집니다.

```html
<!-- 크기만 잡아두는 placeholder -->
<img src="https://placehold.co/300x200" alt="배너 영역">
```

- 설계도 없이 AI에 전체 페이지 생성을 맡기면 수정 비용이 커질 수 있습니다.
- AI 사용 시에는 **"일부분만 수정 요청"** 이 안전하며, 전체 소스 수정은 예기치 않게 구조가 바뀔 수 있습니다.

### **정리 — 어떤 상황에 무엇을 선택할까**

| 상황 | 선택 |
| :--- | :--- |
| 의미 있는 콘텐츠 이미지 | `<img>` + `alt` |
| 장식/배경 이미지 | `background-image` (CSS 파일 기준 경로) |
| 전체 스케일 조정 | `rem` |
| 컨테이너 비율 레이아웃 | `%` |
| 뷰포트 직접 반응 | `vw / vh` |
| 깊은 중첩 포함 선택 | `A B` (후손 선택자) |
| 바로 아래 자식만 선택 | `A > B` (자식 선택자) |
| float 이후 레이아웃 붕괴 방지 | `clear: both` |
