{/* ────────────────────────────────────────────────────────────
    Component 3: Request vs Session 스코프 체험
──────────────────────────────────────────────────────────── */}
export function ScopeSimulator() {
  const [requestAttrs, setRequestAttrs] = useState({});
  const [sessionAttrs, setSessionAttrs] = useState({});
  const [inputKey, setInputKey] = useState('userInfo');
  const [inputVal, setInputVal] = useState('홍길동');
  const [scope, setScope] = useState('request');
  const [forwarded, setForwarded] = useState(false);
  const [step, setStep] = useState('idle'); // idle | stored | forwarded | redirected

  const store = () => {
    if (!inputKey.trim() || !inputVal.trim()) return;
    if (scope === 'request') setRequestAttrs(prev => ({ ...prev, [inputKey]: inputVal }));
    else setSessionAttrs(prev => ({ ...prev, [inputKey]: inputVal }));
    setStep('stored');
    setForwarded(false);
  };

  const doForward = () => {
    setStep('forwarded');
    setForwarded(true);
    // request scope가 forward 후에도 유지됨 (같은 request)
  };

  const doRedirect = () => {
    setStep('redirected');
    setForwarded(false);
    setRequestAttrs({}); // redirect = 새 request → request scope 초기화
    // session은 유지
  };

  const doLogout = () => {
    setSessionAttrs({});
    setRequestAttrs({});
    setStep('idle');
    setForwarded(false);
  };

  const scopeColors = { request: '#3b82f6', session: '#10b981' };

  const wrap = { margin: '32px 0', borderRadius: '18px', overflow: 'hidden', border: '1px solid var(--ifm-color-emphasis-300)', background: 'var(--ifm-background-surface-color)' };
  const ScopeBox = ({ title, color, attrs, note }) => (
    <div style={{ flex: 1, padding: '16px', borderRadius: '12px', border: `2px solid ${color}40`, background: `${color}08` }}>
      <div style={{ fontWeight: '700', fontSize: '13px', color, marginBottom: '10px' }}>{title}</div>
      {Object.keys(attrs).length === 0
        ? <div style={{ fontSize: '12px', color: 'var(--ifm-color-emphasis-400)', fontStyle: 'italic' }}>비어 있음</div>
        : Object.entries(attrs).map(([k, v]) => (
          <div key={k} style={{ display: 'flex', gap: '6px', marginBottom: '5px', fontSize: '12px' }}>
            <span style={{ fontFamily: 'monospace', color, fontWeight: '600' }}>"{k}"</span>
            <span style={{ color: 'var(--ifm-color-emphasis-400)' }}>→</span>
            <span style={{ fontFamily: 'monospace' }}>"{v}"</span>
          </div>
        ))}
      {note && <div style={{ marginTop: '10px', fontSize: '11px', color: 'var(--ifm-color-emphasis-400)', borderTop: `1px solid ${color}30`, paddingTop: '8px' }}>{note}</div>}
    </div>
  );

  return (
    <div style={wrap}>
      <div style={{ padding: '18px 24px', borderBottom: '1px solid var(--ifm-color-emphasis-200)', fontWeight: '700', fontSize: '15px' }}>🧪 Request / Session 스코프 체험</div>

      <div style={{ padding: '20px 24px' }}>
        {/* 저장 폼 */}
        <div style={{ display: 'flex', gap: '8px', flexWrap: 'wrap', alignItems: 'flex-end', marginBottom: '16px' }}>
          <div>
            <div style={{ fontSize: '11px', fontWeight: '600', color: 'var(--ifm-color-emphasis-500)', marginBottom: '4px' }}>key</div>
            <input value={inputKey} onChange={e => setInputKey(e.target.value)} style={{ padding: '7px 10px', borderRadius: '8px', border: '1px solid var(--ifm-color-emphasis-300)', background: 'var(--ifm-background-color)', color: 'var(--ifm-color-content)', fontSize: '13px', fontFamily: 'monospace', width: '120px' }} />
          </div>
          <div>
            <div style={{ fontSize: '11px', fontWeight: '600', color: 'var(--ifm-color-emphasis-500)', marginBottom: '4px' }}>value</div>
            <input value={inputVal} onChange={e => setInputVal(e.target.value)} style={{ padding: '7px 10px', borderRadius: '8px', border: '1px solid var(--ifm-color-emphasis-300)', background: 'var(--ifm-background-color)', color: 'var(--ifm-color-content)', fontSize: '13px', width: '120px' }} />
          </div>
          <div>
            <div style={{ fontSize: '11px', fontWeight: '600', color: 'var(--ifm-color-emphasis-500)', marginBottom: '4px' }}>스코프</div>
            <div style={{ display: 'flex', gap: '4px' }}>
              {['request', 'session'].map(s => (
                <button key={s} onClick={() => setScope(s)} style={{ padding: '7px 12px', borderRadius: '8px', border: `2px solid ${scope === s ? scopeColors[s] : 'var(--ifm-color-emphasis-300)'}`, background: scope === s ? `${scopeColors[s]}15` : 'transparent', color: scope === s ? scopeColors[s] : 'var(--ifm-color-content-secondary)', fontWeight: '700', fontSize: '12px', cursor: 'pointer' }}>
                  {s}
                </button>
              ))}
            </div>
          </div>
          <button onClick={store} style={{ padding: '8px 16px', borderRadius: '8px', border: 'none', background: scopeColors[scope], color: '#fff', fontWeight: '700', fontSize: '13px', cursor: 'pointer' }}>
            setAttribute
          </button>
        </div>

        {/* 스코프 박스 */}
        <div style={{ display: 'flex', gap: '12px', marginBottom: '16px' }}>
          <ScopeBox
            title="📦 Request Scope"
            color="#3b82f6"
            attrs={requestAttrs}
            note="forward 이후에도 유지 / redirect하면 사라짐"
          />
          <ScopeBox
            title="🗝️ Session Scope"
            color="#10b981"
            attrs={sessionAttrs}
            note="여러 요청에 걸쳐 유지 / invalidate() 시 삭제"
          />
        </div>

        {/* 액션 버튼 */}
        <div style={{ display: 'flex', gap: '8px', flexWrap: 'wrap' }}>
          <button onClick={doForward} style={{ padding: '7px 14px', borderRadius: '8px', border: 'none', background: '#3b82f6', color: '#fff', fontWeight: '700', fontSize: '12px', cursor: 'pointer' }}>
            forward → JSP
          </button>
          <button onClick={doRedirect} style={{ padding: '7px 14px', borderRadius: '8px', border: 'none', background: '#f59e0b', color: '#fff', fontWeight: '700', fontSize: '12px', cursor: 'pointer' }}>
            sendRedirect (새 요청)
          </button>
          <button onClick={doLogout} style={{ padding: '7px 14px', borderRadius: '8px', border: 'none', background: '#ef4444', color: '#fff', fontWeight: '700', fontSize: '12px', cursor: 'pointer' }}>
            session.invalidate()
          </button>
        </div>

        {/* 상태 메시지 */}

## HTTP 메서드와 데이터 위치

프로토콜은 통신 규칙이다. 웹에서는 HTTP/HTTPS를 사용하며, 요청 메서드가 목적을 결정한다.

- **GET**: URL 쿼리스트링으로 전달 — 캐싱 가능, 민감 데이터 절대 금지
- **POST**: Body로 전달 — 숨김 전송, 대용량 가능, `Content-Type` 헤더 필수
- **PUT/PATCH**: 수정(전체/부분), **DELETE**: 삭제

강의에서는 실습 단계를 GET/POST 중심으로 단순화했다. 브라우저 주소창으로는 GET만 직접 테스트 가능하므로 POST 이후는 Postman을 활용한다.

<HttpMethodCompare />

### HTTP 상태 코드

| 코드 | 의미 | 주요 상황 |
|---|---|---|
| **200** | 성공 | 정상 처리 |
| **302** | 리다이렉트 | `sendRedirect()` 응답 |
| **404** | 리소스 없음 | URL/엔드포인트 미존재 |
| **500** | 서버 오류 | 서블릿 내부 예외 |

Postman에서는 화면(JSP) 없이도 **상태 코드로 정상 처리 여부를 우선 확인**한다.

## 서블릿 컨트롤러 설계 (맵핑 테이블)

엑셀 설계서를 기준으로 컨트롤러 패키지에 서블릿을 생성한다. 기능별 GET/POST 배분 기준은 간단하다.

> 조회·화면 이동 → **GET**, 입력·저장 → **POST**

```java
@WebServlet("/login")
public class LoginServlet extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response) {
        // 로그아웃: GET /login → session.invalidate() → 루트로 리다이렉트
    }

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response) {
        // 로그인: POST /login → id/pw 수신 → DAO → 세션 저장
    }
}
```

ID 중복 검사처럼 GET/POST 모두 허용이 필요한 경우 동일 로직을 두 번 쓰지 않고 **private 메서드로 위임**한다.

```java
@Override protected void doGet(HttpServletRequest req, HttpServletResponse res) throws ServletException, IOException {
    process(req, res);
}
@Override protected void doPost(HttpServletRequest req, HttpServletResponse res) throws ServletException, IOException {
    process(req, res);
}
// 중복 로직을 단일 private 메서드로 통합
private void process(HttpServletRequest req, HttpServletResponse res) { ... }
```

## 인코딩 처리 — 가장 먼저

모든 서블릿에서 첫 번째로 처리할 것은 **인코딩**이다. 한글 깨짐을 방지한다.

```java
// 클라이언트 → 서버 (POST 요청 파라미터)
request.setCharacterEncoding("UTF-8");

// 서버 → 클라이언트 (응답 HTML)
response.setContentType("text/html; charset=UTF-8");
```

> Spring Boot에서는 `application.properties`의 `server.servlet.encoding.charset=UTF-8` 한 줄로 해결된다. 서블릿은 매 요청마다 직접 설정해야 한다는 차이가 있다.

## Request / Session 스코프

서블릿에서 JSP로 값을 넘길 때 **스코프(scope)** 개념이 핵심이다.

| 스코프 | 유효 범위 | 저장 | 삭제 |
|---|---|---|---|
| **Request** | 한 번의 forward 범위 | `request.setAttribute(k, v)` | redirect 시 자동 소멸 |
| **Session** | 로그인 ~ 로그아웃 전체 | `session.setAttribute(k, v)` | `session.invalidate()` |

- JSP에서는 EL `${key}`로 꺼낸다.
- 스코프에서 꺼낸 값은 `Object` 타입 → **다운캐스팅 필요**

```java
HttpSession session = request.getSession();
LoginDto loginDto = (LoginDto) session.getAttribute("loginDto"); // 다운캐스팅
```

## web-inf 보안 영역 & forward/redirect

`web-inf` 폴더는 **외부 URL로 직접 접근이 차단**되는 보안 영역이다. 마이페이지, 내부 결과 화면, 오류 페이지는 여기에 두고 서블릿을 통해서만 진입시킨다.

```
webapp/
├── index.jsp          ← 직접 접근 가능 (공개 페이지)
└── WEB-INF/
    └── views/
        ├── main.jsp       ← 직접 접근 불가 → forward로만 이동
        ├── userInfo.jsp
        └── error/
            └── error.html
```

<ForwardRedirectViz />

```java
// forward — 서버 내부 이동, request 유지
RequestDispatcher rd = request.getRequestDispatcher("/WEB-INF/views/userInfo.jsp");
rd.forward(request, response);

// redirect — 클라이언트에게 새 URL 요청 지시, request 초기화
response.sendRedirect("/");
```

## 로그인 구현 흐름

```java
@Override
protected void doPost(HttpServletRequest request, HttpServletResponse response)
        throws ServletException, IOException {

    request.setCharacterEncoding("UTF-8");
    response.setContentType("text/html; charset=UTF-8");

    String id = request.getParameter("id");
    String pw = request.getParameter("pw");

    LoginDto loginDto = new LoginDto(id, pw);
    LoginDto result = dao.login(loginDto); // DB 조회

    if (result != null) {
        // 성공: Session에 저장 후 메인 JSP로 포워드
        HttpSession session = request.getSession();
        session.setAttribute("loginDto", result);
        RequestDispatcher rd = request.getRequestDispatcher("/WEB-INF/views/main.jsp");
        rd.forward(request, response);
    } else {
        // 실패: 스크립트로 alert 후 뒤로 가기
        PrintWriter out = response.getWriter();
        out.println("<script>alert('로그인 실패'); history.back();</script>");
    }
}
```

Postman에서 `x-www-form-urlencoded`로 `id`, `pw` 값을 보내면 성공 시 쿠키에 **JSESSIONID**가 저장된다. 이후 요청에서 이 쿠키가 자동 전송되어 세션이 유지된다.

### 로그아웃

```java
@Override
protected void doGet(HttpServletRequest request, HttpServletResponse response)
        throws ServletException, IOException {
    HttpSession session = request.getSession(false); // 없으면 null 반환
    if (session != null) session.invalidate();
    response.sendRedirect("/");
}
```

## 사용자 정보 수정 — Builder 패턴 활용

수정 기능은 GET(폼 이동)과 POST(반영)를 분리한다. 일부 필드만 변경될 수 있으므로 **Builder 패턴**으로 DTO를 구성한다.

```java
@Override
protected void doPost(HttpServletRequest request, HttpServletResponse response)
        throws ServletException, IOException {

    request.setCharacterEncoding("UTF-8");

    HttpSession session = request.getSession(false);
    if (session == null) { response.sendRedirect("/"); return; }

    LoginDto loginDto = (LoginDto) session.getAttribute("loginDto");
    String email    = request.getParameter("email");
    String password = request.getParameter("password");

    // 빈 문자열 처리 후 Builder로 DTO 조립
    UserModifyDto dto = UserModifyDto.builder()
            .id(loginDto.getId())
            .email(email.isEmpty() ? null : email)
            .password(password.isEmpty() ? null : password)
            .build();

    int cnt = dao.updateUser(dto);
    if (cnt > 0) {
        session.invalidate(); // 수정 후 세션 초기화
        response.sendRedirect("/");
    } else {
        response.sendRedirect("/userModify"); // 실패 → 폼 재표시
    }
}
```

## 회원 탈퇴 — 논리 삭제 & 오류 페이지

실무에서 사용자 삭제는 **물리 삭제가 아니라 `enable` 플래그 변경**(논리 삭제)으로 처리한다.

```java
// DAO 내부: DELETE가 아니라 UPDATE

오류 페이지는 `web-inf`에 두고, `meta refresh`로 일정 시간 후 자동 이동을 구현한다.

<meta http-equiv="refresh" content="3; url=/">
<p>오류가 발생했습니다. 3초 후 홈으로 이동합니다.</p>
```

## 정리

오늘 구현한 기능의 공통 패턴은 단 하나다.

```
요청 수신 (doGet/doPost)
  → 인코딩 설정
  → 세션 유효성 확인 (필요 시)
  → 파라미터 수신 → DTO 구성
  → DAO 실행
  → 성공: 스코프 저장 + forward / redirect
  → 실패: 스크립트 alert 또는 error 페이지 forward
```

세션 체크 로직이 서블릿마다 중복되는 문제는 추후 **Filter로 공통화**하면 해결된다. 전체 기능 구축 후 리팩토링 대상이다.
