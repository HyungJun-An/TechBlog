`int[]` 하나로 최솟값만 저장하던 다익스트라를 `PriorityQueue<Integer>[]` 배열로 확장해 K번째 경로까지 기록하는 문제입니다. 플레티넘IV  난이도답게 "왜?"라는 질문이 끊이지 않았습니다.

<!-- truncate -->

## 문제 설명

1번 노드에서 출발해 각 노드까지의 **K번째 최단 경로** 거리를 구합니다. K번째 경로가 없으면 -1을 출력합니다.

**입력 조건**
- 정점 수 $N$: $1 \leq N \leq 1,000$
- 간선 수 $M$: $1 \leq M \leq 200,000$
- 경로 순위 $K$: $1 \leq K \leq 100$

[백준 1854번](https://www.acmicpc.net/problem/1854)

## 처음 접근 — 일반 다익스트라로 시도

처음엔 각 노드마다 다익스트라를 따로 돌려서 최단 거리를 구하려 했습니다.

```java
// 각 노드를 시작점으로 다익스트라 N번 실행
for (int i = 1; i <= n; i++) {
    int ans = find(i, n, k, node);
    System.out.println(ans == Integer.MAX_VALUE ? -1 : ans);
}
```

문제는 이 접근이 **K번째를 구할 방법이 없다**는 것입니다. 일반 다익스트라는 `int[]`에 최솟값 하나만 저장하므로, K번째까지 추적할 공간이 없습니다.

## 핵심 아이디어 — 노드별 K등 성적표

`int[]` → `PriorityQueue<Integer>[]`로 교체합니다. 각 노드마다 상위 K개의 거리를 저장하는 **최대 힙(내림차순 PQ)**을 둡니다.

```java
PriorityQueue<Integer>[] dists = new PriorityQueue[n + 1];
for (int i = 1; i <= n; i++) {
    dists[i] = new PriorityQueue<>(Collections.reverseOrder()); // 최대 힙
}
```

최대 힙을 쓰는 이유: `peek()`가 항상 **현재 저장된 것 중 가장 큰 값(=K등)**  을 반환하므로, 새 경로와 비교해 갱신 여부를 $O(\log K)$에 판단할 수 있습니다.

### 삽입 규칙 — Case A / B

새 경로 `nextDist`가 들어올 때:

```java
// Case A: 아직 K개가 안 찼으면 무조건 추가
if (dists[next.d].size() < k) {
    dists[next.d].add(nextDist);
    pq.add(new Edge(next.d, nextDist));
}
// Case B: K개가 꽉 찼고, 현재 K등(peek)보다 작으면 교체
else if (dists[next.d].peek() > nextDist) {
    dists[next.d].poll();       // 기존 K등 제거
    dists[next.d].add(nextDist); // 새 경로 삽입
    pq.add(new Edge(next.d, nextDist));
}
```

## 풀면서 생긴 의문들

### Q1. 1번에서 1번으로 가는 거리가 왜 -1이지?

보통 시작점은 거리 0인데, 예제 출력에서 1번 노드가 -1입니다.

이 문제에서 '경로'는 **최소 1개 이상의 간선을 지나야** 합니다. 가만히 서 있는 상태(0)는 경로로 치지 않고, 돌아오는 사이클이 있을 때만 경로로 인정합니다. 사이클이 없으면 1번→1번 경로 자체가 존재하지 않으므로 -1이 됩니다.

### Q2. K개를 꽉 채워야 하는 이유가 뭐지?

바구니에 K-1개만 들고 있으면 어떨까? 1등이 새로 들어오면 기존 1등 → 2등, 2등 → 3등으로 밀립니다. K-1번째 자리가 비어있다면 이 도미노에서 데이터가 유실됩니다. **정확한 K등을 유지하려면 K개 자리가 모두 채워져 있어야** 합니다.

### Q3. K개 이후를 버려도 괜찮을까?

다익스트라 탐색용 큐(`pq`)는 항상 **가장 짧은 경로부터** 꺼냅니다. 지금 도착한 경로가 바구니의 K등보다 크거나 같다면, 이후에 올 경로들은 모두 현재보다 길거나 같습니다. 즉, 앞으로 영원히 K등 안에 들 수 없으므로 안심하고 버려도 됩니다.

### Q4. 도착 순서가 뒤죽박죽이어도 K등이 보장될까?

바구니(`dists[i]`)는 새 경로를 추가할 때마다 내부적으로 힙 정렬을 수행합니다. 1등이 늦게 오든 4등이 먼저 오든, 바구니는 항상 자기 안에서 상위 K개를 유지합니다.

## 최종 풀이 코드

```java
/*
    백준 1854 - K번째 최단 경로 찾기
    1. 아이디어
        - 일반 다익스트라는 최단 거리 '하나'만 저장하지만, 이 문제는 'K개'를 저장해야 함.
        - 각 노드마다 우선순위 큐(최대 힙, PriorityQueue<Integer>)를 사용하여 K개의 경로를 유지함.
        - 다익스트라 탐색 중 새로운 경로(nextDist)를 발견했을 때:
            A. 해당 노드의 바구니가 K개 미만이면: 무조건 추가 후 탐색용 PQ에 넣음.
            B. 바구니가 K개 꽉 찼는데, 현재 경로가 K등(peek)보다 작으면:
               기존 K등을 poll()하고 새 경로를 add()한 뒤 탐색용 PQ에 넣음.
        - 1번 노드에서 시작하는 다익스트라 한 번으로 모든 노드의 K번째 경로를 확정함.

    2. 시간복잡도
        - 다익스트라 기본: O(E log V)
        - 각 간선마다 K개들이 바구니를 관리(log K)하므로: O(E log V * log K)
        - 약 250,000 * 10 * 7 = 약 1,750,000 연산 (2초 제한 내 충분히 가능)

    3. 자료구조
        - 노드 정보: ArrayList<ArrayList<Edge>> (인접 리스트)
        - K등 기록 바구니: PriorityQueue<Integer>[] dists (최대 힙: Collections.reverseOrder())
        - 탐색 도구: PriorityQueue<Edge> pq (최소 힙: 가중치 작은 순서부터 탐색)
        - 데이터 클래스: Edge {int d 목적지 노드, int w 현재까지의 누적 가중치}
*/
import java.io.*;
import java.util.*;

public class K번째최단경로찾기 {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());
        int n = Integer.parseInt(st.nextToken());
        int m = Integer.parseInt(st.nextToken());
        int k = Integer.parseInt(st.nextToken());
        ArrayList<ArrayList<Edge>> node = new ArrayList<>();
        for(int i=0; i<=n; i++) node.add(new ArrayList<>());
        for(int i=0; i<m; i++) {
            st = new StringTokenizer(br.readLine());
            int u = Integer.parseInt(st.nextToken());
            int v = Integer.parseInt(st.nextToken());
            int w = Integer.parseInt(st.nextToken());
            node.get(u).add(new Edge(v, w));
        }
        PriorityQueue<Integer>[] dists = new PriorityQueue[n+1];
        for(int i=1; i<=n; i++) dists[i] = new PriorityQueue<>(Collections.reverseOrder());
        find(n,k,node,dists);
        for(int i=1; i<=n; i++) {
            // 바구니가 K개만큼 안 찼다는 건 K번째 경로가 없다는 뜻
            if (dists[i].size() < k) {
                System.out.println("-1");
            } else {
                // 최대 힙의 root(peek)는 항상 K번째로 작은 값(K등)임
                System.out.println(dists[i].peek());
            }
        }
    }
    public static void find(int n, int k, ArrayList<ArrayList<Edge>> node, PriorityQueue<Integer>[] dists) {
        PriorityQueue<Edge> pq = new PriorityQueue<>((e1,e2) -> e1.w - e2.w);
        dists[1].add(0);
        pq.add(new Edge(1, 0));

        while(!pq.isEmpty()) {
            Edge nowEdge = pq.poll();
            int now = nowEdge.d;
            int weight = nowEdge.w;

            //인접 노드 탐색
            for(Edge next : node.get(now)) {
                int nextDist = next.w + weight;  //지금까지 온 거리 + 다음 도로 거리

                //Case A : 아직 K등까지 성적표가 다 차지 않았을 때 (큐가 K개만큼 다 차지 않았을 때는 무조건 추가)
                if (dists[next.d].size() < k) {
                    dists[next.d].add(nextDist);
                    pq.add(new Edge(next.d, nextDist));
                }
                //Case B : K개가 꽉 찼을 때 기존 큐에 K등(가장 큰 값) 보다 새로들어온 값이 작을때
                else if (dists[next.d].peek() > nextDist) {
                    dists[next.d].poll(); // 기존 K값 버리기
                    dists[next.d].add(nextDist); //새로운 K값 넣기
                    pq.add(new Edge(next.d, nextDist)); // 큐에 넣고 다음탐색 진행
                }
            }
        }
    }
}
class Edge {
    int d;
    int w;
    Edge(int d, int w ) {
        this.d = d;
        this.w = w;
    }
}
```

## 시간복잡도

| 요소 | 복잡도 |
|------|--------|
| 다익스트라 기본 | $O(E \log V)$ |
| 노드별 K등 바구니 관리 | $\times O(\log K)$ |
| **전체** | $O(E \log V \log K)$ |

$200,000 \times \log 1,000 \times \log 100 \approx 200,000 \times 10 \times 7 = 14,000,000$ — 2초 제한에 충분합니다.

## 배운 점

일반 다익스트라와의 핵심 차이:

| 구분 | 일반 다익스트라 | K번째 다익스트라 |
|------|----------------|-----------------|
| 노드별 저장소 | `int[]` (최솟값 1개) | `PriorityQueue<Integer>[]` (상위 K개) |
| 갱신 조건 | `ans[d] > 새 거리` | 바구니가 K개 미만 or K등보다 작음 |
| 종료 조건 | 큐가 빌 때 | 큐가 빌 때 (동일) |
| 힙 방향 | 최소 힙 | 탐색: 최소 힙 / 바구니: **최대 힙** |

탐색 큐는 최소 힙, 바구니는 최대 힙 — 두 방향을 동시에 써야 한다는 게 이 문제의 묘미입니다.
