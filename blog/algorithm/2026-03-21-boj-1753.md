정답은 맞는데 메모리 초과 — 다익스트라를 `Queue`로 짜면 생기는 일입니다. `PriorityQueue` + **갱신될 때만 삽입** 패턴이 왜 필수인지 직접 부딪히며 배웠습니다.

<!-- truncate -->

## 문제 설명

방향 그래프에서 특정 시작점으로부터 모든 정점까지의 최단 거리를 구합니다.

**입력 조건**
- 정점 수 $V$: $1 \leq V \leq 20,000$
- 간선 수 $E$: $1 \leq E \leq 300,000$
- 가중치 $w$: $1 \leq w \leq 10$

[백준 1753번](https://www.acmicpc.net/problem/1753)

## 처음 제출한 코드 — 정답인데 메모리 초과

```java
Queue<Integer> q = new LinkedList<>();
q.add(s);
while (!q.isEmpty()) {
    int now = q.poll();
    for (Edge next : node.get(now)) {
        ans[next.d] = Math.min(ans[now] + next.w, ans[next.d]);
        q.add(next.d); // 갱신 여부와 무관하게 무조건 삽입
    }
}
```

로컬에서 돌리면 답은 정확하게 나옵니다. 그런데 백준 제출 결과는 **메모리 초과**였습니다.

### 왜 메모리가 터질까?

일반 `Queue`는 **갱신 여부와 상관없이** 탐색한 모든 노드를 큐에 넣습니다. 사이클이 없어도 같은 노드가 수십~수백 번 큐에 쌓일 수 있습니다.

```
노드 A를 방문 → B, C, D를 큐에 삽입
노드 B를 방문 → A, C, D를 또 큐에 삽입
노드 C를 방문 → A, B, D를 또 큐에 삽입
...
```

$E = 300,000$ 규모에서 이 폭발적 증가가 허용 메모리를 초과시킵니다. **정답 배열은 올바르지만 큐가 메모리를 잡아먹는** 황당한 상황이 생기는 것입니다.

## 수정된 코드 — PriorityQueue + 조건부 삽입

핵심 변경은 두 가지입니다.

**1. PriorityQueue로 교체 — 가중치 기준 오름차순**

```java
PriorityQueue<Edge> q = new PriorityQueue<>((e1, e2) -> e1.w - e2.w);
q.add(new Edge(s, 0));
```

가장 짧은 경로를 먼저 꺼내므로, 한 번 최솟값이 확정된 노드는 다시 처리할 필요가 없습니다.

**2. 갱신될 때만 큐에 삽입**

```java
// 이미 더 짧은 경로로 처리된 노드는 건너뜀
if (ans[now] < weight) continue;

for (Edge next : node.get(now)) {
    if (ans[next.d] > ans[now] + next.w) {      // 갱신되는 경우에만
        ans[next.d] = ans[now] + next.w;
        q.add(new Edge(next.d, ans[next.d]));    // 큐에 삽입
    }
}
```

`if (ans[d] > ans[now] + w)` 조건 하나로 큐 삽입 횟수를 $O(E)$ 이하로 제한합니다.

## 최종 풀이 코드

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());
        int v = Integer.parseInt(st.nextToken());
        int e = Integer.parseInt(st.nextToken());
        int s = Integer.parseInt(br.readLine());

        int[] ans = new int[v + 1];
        Arrays.fill(ans, Integer.MAX_VALUE);
        ans[s] = 0;

        ArrayList<ArrayList<Edge>> node = new ArrayList<>();
        for (int i = 0; i <= v; i++) node.add(new ArrayList<>());

        for (int i = 0; i < e; i++) {
            st = new StringTokenizer(br.readLine());
            int u = Integer.parseInt(st.nextToken());
            int d = Integer.parseInt(st.nextToken());
            int w = Integer.parseInt(st.nextToken());
            node.get(u).add(new Edge(d, w));
        }

        PriorityQueue<Edge> q = new PriorityQueue<>((e1, e2) -> e1.w - e2.w);
        q.add(new Edge(s, 0));

        while (!q.isEmpty()) {
            Edge nowEdge = q.poll();
            int now = nowEdge.d;
            int weight = nowEdge.w;

            if (ans[now] < weight) continue; // 이미 더 짧은 경로로 확정됨

            for (Edge next : node.get(now)) {
                if (ans[next.d] > ans[now] + next.w) {
                    ans[next.d] = ans[now] + next.w;
                    q.add(new Edge(next.d, ans[next.d]));
                }
            }
        }

        StringBuilder sb = new StringBuilder();
        for (int i = 1; i < ans.length; i++) {
            sb.append(ans[i] == Integer.MAX_VALUE ? "INF" : ans[i]).append('\n');
        }
        System.out.print(sb);
    }
}

class Edge {
    int d, w;
    Edge(int d, int w) { this.d = d; this.w = w; }
}
```

## 시간복잡도 & 메모리

| 구분 | Queue 버전 | PriorityQueue 버전 |
|------|-----------|-------------------|
| 시간 | $O(VE)$ (최악) | $O(E \log V)$ |
| 큐 크기 | 폭발적 증가 | 최대 $O(E)$ |
| 결과 | 메모리 초과 | 통과 |

$E \log V = 300,000 \times \log 20,000 \approx 300,000 \times 14.3 \approx 4,300,000$

## 배운 점

다익스트라의 병목은 시간만이 아닙니다. **큐에 얼마나 많은 데이터가 쌓이는가**도 중요합니다.

두 가지 규칙을 세트로 기억하면 됩니다:

- `PriorityQueue` — 최솟값을 먼저 꺼내 불필요한 재처리를 막는다
- **갱신 조건부 삽입** — `if (ans[d] > ans[now] + w)` 를 통과할 때만 큐에 넣는다

이 두 조건이 빠지면 정답은 나오지만 메모리가 터집니다. 다익스트라는 항상 이 패턴으로 구현해야 합니다.
